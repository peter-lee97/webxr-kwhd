# Implementation Plan: Browser localStorage for Captures

## Current State
- **Frontend**: Vite (v8.0.10) + Three.js (v0.184.0) - Static SPA
- **Storage**: Server-side via `/save-capture` endpoint (saves to `captures/` directory)
- **Dashboard**: Express server with authentication to read server files

## New Requirement
Move captures storage from **server-side** to **browser localStorage**:
1. Save captured images to localStorage (not server)
2. Dashboard reads from localStorage (no API calls)
3. No authentication required (client-side only)
4. Simple, self-contained solution

## Architecture Change

**From**: Browser → Server API → File System
**To**: Browser → localStorage → Browser Dashboard

## Implementation Plan

### 1. Update Main App (src/main.js)
Modify `captureScene()` function to save to localStorage:

```javascript
async function captureScene() {
    captureFlash.style.display = 'block';
    audioManager.playShutter();

    captureCounter++;
    const name = `capture_${captureCounter.toString().padStart(3, '0')}`;

    const countEl = document.getElementById('vf-capture-count');
    if (countEl) countEl.textContent = captureCounter.toString().padStart(3, '0');

    renderer.render(scene, camera);
    const dataUrl = renderer.domElement.toDataURL('image/png');

    try {
        saveCaptureToLocalStorage(name, dataUrl);
        console.log(`Capture saved to localStorage: ${name}`);
    } catch (error) {
        console.error('Failed to save to localStorage:', error);
        showMessage(`Storage full: ${error.message}`, true);
    }

    setTimeout(() => {
        captureFlash.style.display = 'none';
    }, 150);
}

function saveCaptureToLocalStorage(name, dataUrl) {
    const captures = getCapturesFromStorage();
    const capture = {
        id: Date.now(),
        name,
        dataUrl,
        size: dataUrl.length,
        date: new Date().toISOString()
    };
    captures.unshift(capture);
    saveCapturesToStorage(captures);
}

function getCapturesFromStorage() {
    const stored = localStorage.getItem('vr_captures');
    return stored ? JSON.parse(stored) : [];
}

function saveCapturesToStorage(captures) {
    try {
        localStorage.setItem('vr_captures', JSON.stringify(captures));
    } catch (error) {
        if (error.name === 'QuotaExceededError') {
            const message = 'Storage quota exceeded. Consider deleting old captures.';
            console.error(message);
            alert(message);
        }
        throw error;
    }
}
```

### 3. Update Dashboard (dashboard.html)
Change from API calls to localStorage reads:

```javascript
function loadCaptures() {
    captures = getCapturesFromStorage();
    renderCaptures();
}

async function deleteFile(filename) {
    if (!confirm(`Are you sure you want to delete ${filename}?`)) {
        return;
    }

    try {
        captures = captures.filter(c => c.name !== filename);
        saveCapturesToStorage(captures);
        selectedFiles.delete(filename);
        renderCaptures();
        showMessage(`Deleted ${filename}`);
    } catch (error) {
        showMessage(error.message, true);
    }
}

function downloadFile(filename) {
    const capture = captures.find(c => c.name === filename);
    if (!capture) return;

    const link = document.createElement('a');
    link.href = capture.dataUrl;
    link.download = filename;
    document.body.appendChild(link);
    link.click();
    document.body.removeChild(link);
    showMessage(`Downloaded ${filename}`);
}
```

Remove authentication prompts (no longer needed).

## Benefits of localStorage Approach

1. **No server required** - Pure client-side
2. **Simpler deployment** - Static hosting only
3. **No authentication** - Privacy by default
4. **Faster** - No network calls for save/load
5. **Offline capable** - Works without network

## Limitations and Mitigations

### localStorage Limitations
- **Quota**: ~5-10MB per domain (browser dependent)
- **Large images**: Full-resolution PNGs can be 500KB-1MB+
- **Many captures**: May hit quota limit

### Mitigations
1. Compress images (reduce quality slightly)
2. Add storage usage indicator
3. Warn when approaching quota
4. Offer to download/delete old captures
5. Consider IndexedDB for larger storage (future enhancement)

## Deployment

### Static Hosting Only (Recommended)
- **Platform**: Netlify, Vercel, GitHub Pages, any CDN
- **Build**: `npm run build`
- **Output**: Serve `dist/` folder
- **HTTPS**: Automatic on most platforms
- **Server**: NOT required (localStorage is client-side)

### Optional Server
Can still use simple HTTP server if needed:
```bash
npm install -g serve
serve -s dist
```
